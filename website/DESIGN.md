## Critique against the brief
Avoid a generic grid of decorative feature cards. The actual notebook is the main graphic; view tabs and enlargement controls let visitors inspect it. Blue light belongs behind the product. Keep headings white rather than applying a gradient or accenting one arbitrary word. Do not use invented customers, testimonials or usage counts. Feature and provider claims follow the current release, including preview status and Linux capture limits.

## Motion and interaction
One restrained entrance for the hero. Use motion for tab changes, menus and dialogs. Respect reduced motion. No autoplay audio, scroll hijacking, perpetual decorative floating or repeated reveal-on-scroll effects. Navigation, installer choices, search, FAQs, source links and copy actions must work with keyboard input.

## Publishing
The user selected public GitHub Pages at https://mrfost07.github.io/noter.ai/. Keep build and deployment in the existing repository. Use relative links so nested documentation and the project subpath work on direct navigation. Self-host fonts and assets. No analytics or sign-in is needed for this public website.

## Real screenshots

The product sections use the user-provided desktop screenshots of notes, meeting playback and the assistant. Preserve the entire screenshot aspect ratio. Hero view tabs and an accessible enlargement dialog make the actual app inspectable; do not recreate its interface as illustrative HTML panels.
